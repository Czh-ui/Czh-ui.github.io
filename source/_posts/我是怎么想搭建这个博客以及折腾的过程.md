# 从零开始搭建我的个人博客：一次属于自己的折腾记录

最近，我终于把自己的个人博客搭建起来了。😁

现在回头看，这个网站其实并没有想象中那么复杂，但从一开始什么都没有，到最后真正让它上线，中间还是经历了不少折腾。(❁´◡`❁)

所以我想把整个过程记录下来（还有是因为被某鸟压力催更）。

一方面是给现在的自己留个记录，另一方面也是希望以后再回来看这篇文章的时候，可以知道自己当时到底是怎么把这个博客一点一点做出来的。(虽然以后可能摸鱼时间更多)

---

## 一、为什么突然想做一个博客

最开始其实没有什么特别复杂的原因。

上大学以后，我开始慢慢接触各种各样的东西。

比如 Arduino、单片机、ESP32、C++，吧啦吧啦的各种（都不精通嘛😒）。

有时候一个问题可能会折腾几个小时，最后好不容易解决了，过一段时间又忘记自己当时是怎么解决的。

而且大学几年里肯定还会继续学很多新的东西。

所以我慢慢产生了一个想法：

> 能不能有一个真正属于自己的地方，把这些东西记录下来？

相比把东西零零散散地放在聊天记录、电脑文件夹或者其他平台上，我更想拥有一个完全属于自己的空间。

这里不一定要有很多人看，也不一定要写得多么专业。

只要能够把自己做过的东西、学过的东西和一些想法留下来，我觉得就已经很有意义了。

再加上上个假期我遇到了鱼小鳄——也可以叫他青蛙🐸，他给我看了他自己搭建的个人网站，我感觉非常地有特色，‘诶哟不错哦，给我也整一个’的想法也出来了。😍

于是，我开始尝试自己搭一个博客。

---

# 二、我选择了什么工具

确定要做之后，我首先需要解决的就是：

> 用什么来做？

其实可以选择很多方法。

比如自己从 HTML、CSS、JavaScript 开始写，也可以使用 WordPress，或者使用一些前端框架。

但对于我来说，直接从零开发一个完整的网站有点太复杂(说白了就是懒😜)。

所以最后我选择了：

```text
Hexo
```

Hexo 是一个静态博客框架。

简单理解的话，就是我平时主要负责写 Markdown 文章，然后 Hexo 帮我把这些文章生成真正的网页。

这样以后写新文章的时候，就不用自己重新写 HTML。

---

# 三、第一次把博客跑起来

确定使用 Hexo 以后，我先把 Node.js 和 Git 安装好。

然后创建了自己的博客项目：

```text
D:\MyBlog
```

接着使用 Hexo 初始化项目。

第一次在浏览器中看到：

```text
http://localhost:4000
```

的时候，还是挺有成就感的。

因为这时候它已经不只是一个文件夹，而是真的变成了一个可以运行的网站。

不过那时候的网站还非常普通。

所以接下来真正让我花时间的部分才开始。

---

# 四、选择 Butterfly 作为主题

Hexo 默认的页面比较简单。

所以我又找了一个适合个人博客的主题，最后选择了：

```text
Butterfly
```

现在使用的是 Butterfly 5.7.0。

有了主题以后，博客的基础结构很快就有了。

比如：

```text
首页
文章
标签
分类
归档
侧边栏
```

这样就不用自己从头设计整个博客结构。

不过我也不太想直接使用默认样式。

所以接下来开始慢慢修改。（说实话我自己是拿不定主意要修改什么的，不过我挺随便的，干脆就想到什么搞什么🤣）

---

# 五、把博客改成自己喜欢的样子

这是整个过程中我花时间比较多的部分。

我首先换掉了默认的头像和顶部图片（注意，我的背景和头像其实是我当时没什么高大上的图片，在电脑文件里的最近文件随便搞来的，以后再慢慢改😅）。

然后开始调整网站背景。

最后我选择了比较喜欢的：

```text
蓝色
紫色
青色
```

做成渐变背景，再加入一些柔和的光晕。

整体看起来不会只有一块单调的颜色。

---

## 文章卡片

然后我把首页的文章卡片改成了半透明的玻璃效果。

比如：

```text
透明度
圆角
模糊
阴影
```

这样文章卡片不会再像普通的白色方框，而是会稍微透出后面的背景。

右侧的个人信息卡片也用了类似的设计。

这样整个网站的视觉风格就统一起来了。

最后基本确定成：

> 蓝紫青 + 二次元 + 玻璃拟态（二次元赛高！！！）

这也是我比较喜欢的风格。

---

# 六、自己做了一个 About Me 页面

后来我觉得，一个个人博客如果只有文章，还是有点奇怪。

所以又做了一个：

```text
About Me
```

也就是“关于我”。

里面写了一些简单的内容：

```text
个人介绍
正在学习的东西
学习方向
做过的项目
博客介绍
联系方式
```

同时也加入了 GitHub 和 Email。

这样别人来到我的博客以后，可以比较方便地知道这个网站是谁的，也可以找到我的联系方式（我是社交牛杂症望周知!🥲）。

---

# 七、给博客加一些互动效果

博客虽然已经能用了，但还是感觉有一点太静态。

所以我又开始尝试增加一些简单的 JavaScript 效果。

比如点击网页的时候出现一个小光圈。

还有文章卡片鼠标悬停时会轻微浮起来。

这些特效并没有特别复杂，主要还是为了让网页多一点互动感。

我也尝试过给文章加阅读进度条。

不过后来发现这个功能对整体影响不大，而且调试的时候还遇到了一些问题（其实是发现没啥用还麻烦，真的服了😐）。

最后决定先放着。

我也慢慢发现：

> 做网站不一定什么功能都要加，真正有用的功能才值得留下。

---

# 八、给博客加背景音乐

后来又有了一个比较有意思的想法：

> 能不能让博客有自己的背景音乐？

于是我在：

```text
source/music
```

里面放了一些歌曲。

然后自己写了一个简单的音乐播放器。

现在可以实现：

```text
播放
暂停
上一首
下一首
音量调节
自动播放下一首
展开 / 收起
唱片旋转
```

播放器最后放到了网页右下角。

平时收起来的时候只显示一个小唱片。

点击以后再展开成完整播放器。

这个功能我自己还是挺喜欢的，因为它让博客有了一点属于自己的感觉。

---

# 九、文章页面和代码块

博客做完首页以后，我又开始考虑一个问题：

> 如果以后真的在这里写技术文章，会不会不好看？

因为我可能会记录一些 Arduino、ESP32、C++ 之类的东西，所以代码显示效果还是比较重要的（真的假的😜）。

于是又把文章页面进行了一些调整。

比如：

```text
文章标题
正文间距
图片圆角
引用框
代码块
```

代码块也进行了专门的美化。

最后增加了：

```text
深色代码背景
圆角
横向滚动
代码复制按钮
```

这样以后如果别人看到我的代码，可以直接点击“复制”，不用自己慢慢选中。

---

# 十、博客做好之后，怎么让别人看到

做到这里的时候，我又遇到了另一个问题：

> 本地能运行，但是怎么让别人也能看到？

一开始我甚至觉得是不是需要自己买服务器。

后来查了一些资料以后，发现对于 Hexo 这种静态博客，其实不一定需要自己租服务器。

最后我选择了：

```text
GitHub
+
GitHub Pages
+
GitHub Actions
```

这也是整个部署过程中很重要的一步。

---

# 十一、第一次使用 Git

为了把博客上传到 GitHub，我开始正式使用 Git。

先在博客目录：

```text
D:\MyBlog
```

里面初始化 Git。

然后：

```powershell
git add .
git commit -m "Initial commit"
```

第一次提交的时候还遇到了：

```text
Author identity unknown
```

后来设置了 Git 的用户名和邮箱以后才解决。（我服了😭）

这个过程也算是我第一次比较完整地接触 Git 的基本流程。

---

# 十二、把博客放到 GitHub

之后在 GitHub 创建了自己的仓库：

```text
Czh-ui.github.io
```

然后把本地博客推送进去。

通过：

```powershell
git push
```

把本地项目上传到了 GitHub。

这时候 GitHub 里已经能看到我的博客源码了。

但这还不意味着网站已经上线。

---

# 十三、使用 GitHub Actions 自动部署（就是这么简单，就是这么低小下😂）

最后我又配置了 GitHub Actions。

现在整个博客的工作流程是：

```text
修改博客
    ↓
Git add
    ↓
Git commit
    ↓
Git push
    ↓
GitHub Actions
    ↓
安装依赖
    ↓
Hexo generate
    ↓
生成 public
    ↓
GitHub Pages
    ↓
网站更新
```

也就是说，以后我只需要把修改推送到 GitHub，后面的构建和发布就会自动完成。

所以我不需要每次修改博客以后，再自己登录服务器手动部署。

---

# 十四、部署的时候也遇到了不少问题

真正部署的时候，并不是一次就成功了。

---

## 第一个问题：YAML 格式错误

有一次我把网站地址写成了（我醉了）：

```yaml
url: url: https://Czh-ui.github.io
```

导致 Hexo 报错。

最后改成：

```yaml
url: https://Czh-ui.github.io
```

才恢复正常。

这个问题看起来很小，但是配置文件一个符号写错，整个网站都可能无法生成。

---

## 第二个问题：GitHub Pages 走错了构建方式

第一次部署的时候，GitHub Pages 使用了 Jekyll。

结果出现：

```text
The butterfly theme could not be found.
```

因为我的网站实际上是 Hexo + Butterfly，不是 Jekyll。

后来才把 GitHub Pages 的构建方式调整成 GitHub Actions，让 Hexo 在 Actions 环境中自己生成网站。

---

## 第三个问题：CSS 大小写

这个问题让我印象比较深。

我原来的文件路径是：

```text
source/CSS/custom.css
```

而配置中写的是：

```text
/css/custom.css
```

我的电脑是 Windows，所以本地运行完全没有问题。

但是 GitHub Actions 使用的是 Linux 环境，Linux 对大小写是敏感的。

结果就是：

> 本地正常。

> 上线以后 custom.css 全部失效（神**windows可用大写的CSS但是github上不识别啊啊😭）。

最后把文件夹改成：

```text
source/css/custom.css
```

问题才解决。

这个问题也让我第一次比较直观地意识到：

> 本地环境能运行，并不代表换一个环境以后也一定完全正常。
